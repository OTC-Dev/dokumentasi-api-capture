Dokumentasi API v1 Capture

Referensi lengkap semua endpoint /api/v1 di repo capture-api (branch main): parameter, payload, dan bentuk respons. Disusun dari kode route, controller, dan validasi per 22 Oktober 2026. Contoh nilai di respons bersifat ilustrasi; bentuk field mengikuti kode.

Setup & autentikasi

Base URL lokal: http://127.0.0.1:8000/api/v1. Semua route memakai middleware ForceJson (header Accept dipaksa application/json) dan FlexibleMiddleware. Middleware mencoba autentikasi berurutan:

UrutanCaraHeaderCompany & user
1InternalX-Internal-Key (= services.internal_token), X-User-Id, X-Company-IdDari header. Tanpa X-User-Id/X-Company-Id: 422 Missing id header.
2JWTAuthorization: Bearer <token>user_id & company_id dari payload token. Token tidak valid: 401.
3API keyX-API-Key: <key>Dari tabel api_clients (aktif, belum dihapus, expired_at > sekarang). Request & respons dicatat lewat LogApiJob (antrian medium), kecuali respons streaming.

Matriks akses

Setelah lolos autentikasi, path dicek ke daftar izin per cara autentikasi. Tidak cocok: 403 {"status":403,"message":"Forbidden"}.

CaraPath yang diizinkan
InternalSemua endpoint.
API keycompanies, divisions, units, levels, positions, form-datas, assessment-purposes, mail-templates/*, tests, tests/*
JWTcandidates (tanpa sub-path), comparison/*, filters/options, companies, companies/*, divisions, units, levels, positions, team-dynamic/*, users/*, billing/quote, feedbacks

Konvensi respons

Paginasi standar

type = paginate (default) atau all

per_page = 1–100, default 10

page = nomor halaman, default 1

meta = {current_page, per_page, total, last_page}; null saat type=all.

Bentuk sukses

{"status": 200, "message": "…", "data": …, "meta": …}

meta hanya ada di endpoint list.

Bentuk error (global)

422 {"status": 422, "message": "Validation failed", "errors": {…}}

4xx {"status": <kode>, "message": "…"}

500 {"status": 500, "message": "Internal Server Error"}

Hanya JWT (Bearer) atau X-Internal-Key yang lolos; tidak ada pembatasan per user/company di controller. Validasi memakai aturan FIELD_RULES/REQUIRED_FIELDS di controller: POST = field wajib required, lainnya sometimes; PUT = semua sometimes dan minimal satu field valid (bila tidak: 422 errors.payload: ["At least one valid field must be provided."]). Field di luar daftar diabaikan diam-diam. Tidak ada endpoint DELETE untuk grup ini.
